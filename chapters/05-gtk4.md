# 5. GTK 4 Fundamentals

## 5.1 The widget tree

A UI is a **tree of widgets**. A window contains one child; containers contain several children.

```
Adw.ApplicationWindow
└─ Adw.ToolbarView
   ├─ [top]  Adw.HeaderBar
   └─ [content] Gtk.Box (vertical)
      ├─ Gtk.SearchEntry
      └─ Gtk.ScrolledWindow
         └─ Gtk.ListBox
```

GTK4 differences from GTK3 you will see in old tutorials: no `show_all()` (widgets are visible by default), no `pack_start`/`pack_end` for boxes (use `append`/`prepend`), no `add()` on most containers (each has its own `set_child`/`append`), events are replaced by **controllers**, and `Gtk.main()` is replaced by the `Gtk.Application` run loop. Ignore any tutorial using `Gtk.main()` or `import gi.repository.Gtk 3.0`.

## 5.2 Application and window skeleton (class-based)

For anything beyond a demo, subclass:

```js
// src/application.js
import Adw from 'gi://Adw?version=1';
import GObject from 'gi://GObject';
import {Window} from './window.js';

export const Application = GObject.registerClass(
class Application extends Adw.Application {
    constructor() {
        super({application_id: 'io.github.you.PandaManager'});
    }

    vfunc_activate() {                    // called when the app is launched
        let win = this.active_window;
        if (!win)
            win = new Window({application: this});
        win.present();
    }

    vfunc_startup() {                     // called once, before activate
        super.vfunc_startup();
        this._setupActions();
    }

    _setupActions() { /* see Chapter 11 */ }
});
```

```js
// src/main.js
import System from 'system';
import {Application} from './application.js';

new Application().runAsync([System.programInvocationName, ...ARGV]);
```

`vfunc_*` methods override virtual functions of the parent class. Always call `super.vfunc_xxx()` when it makes sense (like in `startup`).

`runAsync` returns a Promise and keeps the loop spinning; `run` blocks and returns an exit code. Either is fine; `runAsync` lets `await` interplay naturally.

Single-instance behaviour is automatic: launch it twice and the second launch sends `activate` to the first process.

## 5.3 Layout: the sizing model

GTK layout is **constraint-free and box-based**. Two key ideas:

1. Each widget reports a **minimum** and **natural** size. The parent decides the final size.
2. You influence placement with **alignment**, **expand**, **margins**, and **size requests**.

| Property | Meaning |
|---|---|
| `halign` / `valign` | `Gtk.Align.FILL` (default), `START`, `CENTER`, `END` |
| `hexpand` / `vexpand` | Ask for spare horizontal/vertical space |
| `margin_top/bottom/start/end` | Space outside the widget |
| `width_request`, `height_request` | Minimum size hint. Avoid; prefer natural sizing |
| `visible` | Show/hide |
| `sensitive` | Enabled/disabled |
| `css_classes` | List of CSS classes, e.g. `['title-1']` |
| `tooltip_text` | Hover text |

Common containers:

| Widget | Use |
|---|---|
| `Gtk.Box` | Row or column (`orientation`, `spacing`). Your 80% layout tool |
| `Gtk.Grid` | Table-like placement (`attach(child, col, row, w, h)`) |
| `Gtk.Stack` | Show one child at a time (pages) |
| `Gtk.Overlay` | Layer widgets on top of each other |
| `Gtk.ScrolledWindow` | Scrolling. **Wrap long lists in this** |
| `Gtk.Paned` | Draggable split |
| `Gtk.Revealer` | Animated show/hide |
| `Gtk.Notebook` | Classic tabs (prefer Adw.ViewStack/TabView) |
| `Gtk.Frame`, `Gtk.Separator` | Visual grouping |
| `Gtk.FlowBox` | Wrapping grid of items |
| `Gtk.CenterBox` | Start/center/end children |

```js
const box = new Gtk.Box({
    orientation: Gtk.Orientation.VERTICAL,
    spacing: 12,
    margin_top: 24, margin_bottom: 24, margin_start: 24, margin_end: 24,
});
box.append(new Gtk.Label({label: 'Hello', halign: Gtk.Align.START}));
box.append(button);
```

Spacing convention: multiples of 6 (6, 12, 18, 24). Do not pixel-pinch.

## 5.5 Events: controllers, not events

GTK4 attaches **event controllers** to widgets:

```js
// keyboard
const keys = new Gtk.EventControllerKey();
keys.connect('key-pressed', (_c, keyval, keycode, state) => {
    if (keyval === Gdk.KEY_Escape) { close(); return true; }   // true = handled
    return false;
});
widget.add_controller(keys);

// click
const click = new Gtk.GestureClick();
click.connect('pressed', (_g, nPress, x, y) => { ... });
widget.add_controller(click);

// hover
const motion = new Gtk.EventControllerMotion();
motion.connect('enter', () => ...);
// also: GestureDrag, GestureLongPress, GestureZoom, EventControllerScroll, DragSource, DropTarget
```

`Gdk` import: `import Gdk from 'gi://Gdk?version=4.0';`. For app-level shortcuts prefer **actions** with accelerators (Chapter 11) over key controllers.

## 5.6 CSS styling

GTK is styled with CSS (a GTK subset). Prefer built-in **style classes** first:

- Typography: `title-1` to `title-4`, `heading`, `caption`, `dim-label`, `monospace`, `numeric`
- Buttons: `suggested-action`, `destructive-action`, `flat`, `pill`, `circular`, `opaque`
- Cards/surfaces: `card`, `boxed-list`, `toolbar`, `osd`
- Status: `success`, `warning`, `error`, `accent`

Full list: https://gnome.pages.gitlab.gnome.org/libadwaita/doc/main/style-classes.html

Custom CSS:

```js
const provider = new Gtk.CssProvider();
provider.load_from_string(`
    .repo-dirty { color: @warning_color; }
    .big-number { font-size: 32px; font-weight: 800; }
`);
Gtk.StyleContext.add_provider_for_display(
    Gdk.Display.get_default(), provider, Gtk.STYLE_PROVIDER_PRIORITY_APPLICATION);
widget.add_css_class('repo-dirty');
```

(`load_from_string` needs recent GTK 4.12+. Older: `load_from_data(css, -1)` / bytes.)

Use libadwaita **named colours** (`@accent_bg_color`, `@window_bg_color`, `@card_bg_color`, `@warning_color`, `@error_color`, `@success_color`) so dark mode and accent colours keep working. Never hard-code hex colours for text or backgrounds.

Debug CSS in the Inspector (`GTK_DEBUG=interactive`, CSS tab).

## 5.7 Lists, the right way

Pick by size and need:

| Situation | Use |
|---|---|
| Up to a few hundred simple rows, settings-like | `Gtk.ListBox` with `boxed-list` class and `Adw.ActionRow`s, ideally `bind_model` |
| Thousands of rows, scroll performance | `Gtk.ListView` (or `GridView`) with a model and factory |
| Table with sortable columns | `Gtk.ColumnView` |
| Dropdown choice | `Gtk.DropDown` |

### ListBox with a model (easy, good-looking)

```js
const list = new Gtk.ListBox({selection_mode: Gtk.SelectionMode.NONE, css_classes: ['boxed-list']});
list.bind_model(store, (pkg) => {
    const row = new Adw.ActionRow({title: pkg.name, subtitle: GLib.format_size(pkg.size)});
    row.add_suffix(new Gtk.Image({icon_name: 'go-next-symbolic'}));
    row.activatable = true;
    return row;                                   // must return a widget
});
```

The function is called when items appear; the list updates automatically when `store` changes.

### ListView with a factory (scalable)

```js
const factory = new Gtk.SignalListItemFactory();

factory.connect('setup', (_f, listItem) => {
    // build the widget ONCE per visible row; rows are recycled
    const label = new Gtk.Label({xalign: 0});
    listItem.set_child(label);
});

factory.connect('bind', (_f, listItem) => {
    // called whenever a row is assigned an item
    const item = listItem.get_item();                  // your GObject
    listItem.get_child().label = item.name;
});

factory.connect('unbind', (_f, listItem) => {
    // disconnect anything you connected in bind
});

const selection = new Gtk.SingleSelection({model: store});
const view = new Gtk.ListView({model: selection, factory});
```

Because rows are **recycled**, never assume a widget belongs to one item forever. Set all state in `bind`, undo it in `unbind`.

### Searching and sorting

```js
const filter = new Gtk.CustomFilter();
filter.set_filter_func((item) => item.name.toLowerCase().includes(query));
const filtered = new Gtk.FilterListModel({model: store, filter});
const sorter = new Gtk.CustomSorter((a, b) => a.size - b.size);   // negative/zero/positive
const sorted = new Gtk.SortListModel({model: filtered, sorter});
// when `query` changes: filter.changed(Gtk.FilterChange.DIFFERENT);
```

## 5.8 Dialogs and popovers

- Prefer **libadwaita dialogs** (`Adw.AlertDialog`, `Adw.Dialog`, `Adw.PreferencesDialog`); see Chapter 6.
- `Gtk.Popover` for small anchored content; `Gtk.MenuButton` + `menu_model` for menus; `Gtk.PopoverMenu` for context menus.
- `Gtk.FileDialog` (GTK 4.10+) replaces `FileChooserDialog` and is async:

```js
const dialog = new Gtk.FileDialog({title: 'Select projects folder'});
try {
    const folder = await dialog.select_folder(window, null);   // needs Gio._promisify (see Ch.9)
    console.log(folder.get_path());
} catch (e) {
    if (!e.matches(Gtk.DialogError, Gtk.DialogError.DISMISSED)) throw e;
}
```

Inside Flatpak the file dialog automatically uses the portal.

## 5.9 Drawing and custom widgets (brief)

- Simple custom drawing: `Gtk.DrawingArea` with `set_draw_func((area, cr, w, h) => { ... cr ... })` using Cairo.
- Custom widgets: subclass `Gtk.Widget` and implement `vfunc_snapshot`, `vfunc_measure`, `vfunc_size_allocate`. Rarely necessary; compose existing widgets first. For charts such as disk usage bars, a `Gtk.LevelBar`, `Gtk.ProgressBar` or a `DrawingArea` is usually enough.

## 5.10 Icons

- Use **icon names**, not files: `icon_name: 'folder-symbolic'`.
- Browse names with the **Icon Library** app (GNOME). Symbolic icons end in `-symbolic`.
- Ship custom icons as SVG in `data/icons/hicolor/scalable/actions/` and register the resource path (Chapter 11).

## 5.11 Accessibility

GTK does most of it for you. Help it: set `tooltip_text` on icon-only buttons, give labels to entries (`Adw.EntryRow` does), do not rely on colour alone to convey state, and test keyboard-only navigation (Tab, Enter, Esc).

> **Remember:** tree of widgets; `Gtk.Box` is your workhorse; controllers handle events; style with classes and named colours; use models + factories for lists; recycle rows correctly.
